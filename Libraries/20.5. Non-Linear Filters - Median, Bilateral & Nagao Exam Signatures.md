## 1. Syntax Matrix - What Breaks vs. What Runs

| You are writing... | Correct form | Fatal handwritten form | Failure mode |
| :--- | :--- | :--- | :--- |
| Median blur | `cv2.medianBlur(img, 5)` | `cv2.medianBlur(img, (5, 5))` | Runtime error (verified: bad-argument) — medianBlur takes a **single odd INTEGER**. |
| Box / Gaussian | `cv2.blur(img, (5, 5))` / `cv2.GaussianBlur(img, (5, 5), s)` | `cv2.blur(img, 5)` | The OTHER dialect — tuples here. Median is the family's lone int. |
| Bilateral | `cv2.bilateralFilter(img, d, sigmaColor, sigmaSpace)` | dropping the 4th argument | Four positional parameters, all required in the common form. |
| From-scratch median | `np.sort(window.ravel())[ksize**2 // 2]` | `np.median` of the wrong window region | The rank formula: sorted flat window, index = K^2 // 2. |
| Bilateral on color | `cv2.bilateralFilter(bgr, ...)` directly | pre-splitting channels unnecessarily | OpenCV handles 1- and 3-channel in one call (range distance = RGB vector norm). |
| Nagao | hand-implemented (no `cv2.nagao`) | inventing `cv2.nagao(...)` | No major library ships it — the exam expects YOUR loops/kernels ([[26.5. Nagao Filtering - 9-Sector Geometry, Kernels & Variance Clamping]]). |

## 3. Trap Deep-Dives

### 3.1 The Median Ksize Dialect
`medianBlur(img, 5)` — one odd integer. Writing `(5, 5)` crashes at the C++ binding (verified). Memorize the trio: **blur/Gaussian = tuple; median = int; bilateral = 4 scalars.** This is the single most-quoted signature trap of the pen-and-paper family.

### 3.2 Why Median Beats Mean on Impulse Noise (the justification, ready to write)
A box filter computes the arithmetic mean: `mean([120, 122, 121, 123, 255]) = 148.2` — the salt value 255 drags the estimate 26 levels upward; the speckle becomes a gray smear. The median sorts the neighborhood `sorted -> [120, 121, 122, 123, 255]` and picks the middle: `122` — the outlier sits at the END of the ranking and never enters the estimate. Rank statistics ignore magnitude; means obey it. That asymmetry is the entire exam answer to "why not a mean filter for salt & pepper".

### 3.3 Why Bilateral Preserves Edges (one-sentence mechanism)
The weight is a product $G_{\sigma_s}(\text{distance}) \cdot G_{\sigma_r}(|I(p) - I(q)|)$: across a step edge the intensity difference is large, so $G_{\sigma_r} \to 0$ and the cross-edge contributions are crushed — smoothing happens only WITHIN each side. Numbers: a 99-level difference with $\sigma_r = 25$ carries weight $\approx 0.0004$ (see [[25.5. Bilateral Filtering - Joint Math, LUT Optimization & Artifacts]] for the worked 1-D example: error drops from +29.65 to +0.29 gray levels).

### 3.4 Nagao's Execution Rules (the 3-line contract)
Fixed 5x5 window; nine overlapping sub-regions (center cross 5 px, 4 cardinal bars 7 px, 4 corner quadrants 7 px); per pixel select $k^* = \arg\min_k \sigma_k^2$ and output $\text{round}(\mu_{k^*})$. Variance flags every sector that straddles an edge; at least one sector always lies along one side — so the average is taken ALONG the contour, never across it.

### 3.5 Filter-vs-Noise Selection Matrix (justification cheat row)

| Noise model | Correct filter | One-line justification |
| :--- | :--- | :--- |
| Salt & pepper | `medianBlur(img, 5)` | Rank order discards 0/255 outliers; linear filters smear them into gray patches. |
| Gaussian + keep edges | `bilateralFilter(img, 9, 75, 75)` | Spatial x radiometric weights suppress cross-edge averaging. |
| Gaussian, edges may blur | `GaussianBlur(img, (5, 5), 1.4)` | Weighted isotropic smoothing; optimal for AWGN L2. |
| Gaussian + corners | Nagao | Variance-selected directional sector averages along the edge. |
