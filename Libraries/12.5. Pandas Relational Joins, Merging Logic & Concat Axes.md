# 12.5. Pandas Relational Joins, Merging Logic & Concat Axes

> Exam-defense companion to [[12. Pandas Relational Operations - Joins, Merging, and Concatenation]]. Verified on pandas 2.2.3.

## 1. Syntax Matrix - What Breaks vs. What Runs

| You are writing... | Correct form | Fatal handwritten form | Failure mode |
| :--- | :--- | :--- | :--- |
| Join | `pd.merge(left, right, on='Key', how='left')` | `df1.merge(df2)` alone | The bare method form IS valid (DataFrame.merge is a Dual Citizen) — but without `on=` and `how=` you get default `inner` on shared columns, rarely what the question asked. The `pd.merge(...)` top-level form with explicit keywords is the exam-safe spelling. |
| Mismatched key names | `pd.merge(df1, df2, left_on='ID_A', right_on='ID_B')` | `on='ID_A'` when the right column is `ID_B` | `KeyError` — no shared column by that name. |
| Vertical stack | `pd.concat([df1, df2], axis=0, ignore_index=True)` | `df1.concat(df2)` | `AttributeError` — concat is top-level only; frames have no `.concat` method (verified). |
| Horizontal align | `pd.concat([df1, df2], axis=1)` | — | Aligns on the shared row INDEX — differing indexes produce NaN padding. |
| Join types | `how='inner' / 'left' / 'right' / 'outer'` | `how='cross'` unthinking | Cross joins explode row counts; the four standard types are the exam set. |

## 2. Exact Signatures and Positional Defaults

```python
merged = pd.merge(patients, departments, on="City", how="left")
merged = pd.merge(df1, df2, left_on="ID_A", right_on="ID_B", how="inner")
stacked = pd.concat([df1, df2], axis=0, ignore_index=True)   # rows, fresh RangeIndex
side    = pd.concat([df1, df2], axis=1)                      # columns, index-aligned
```

Defaults worth memorizing: `pd.merge` -> `how="inner"`; `pd.concat` -> `axis=0`.

## 3. Trap Deep-Dives

### 3.1 Inner by Default — Rows Vanish Silently
The default join keeps only key matches. A "left join" question answered without `how='left'` silently drops every unmatched patient row; no exception is raised, so the error is invisible on paper. Always write `how=` explicitly and annotate the retention rule in a comment (left: all left rows, right-side NaN when unmatched).

### 3.2 concat axis Semantics
`axis=0` stacks **rows** (tables grow taller; column names should match, unmatched ones fill NaN). `axis=1` aligns **columns** side by side on the row index — if the two frames carry different indexes, expect NaN-filled misalignment. `ignore_index=True` (axis=0 habit) rebuilds a clean `RangeIndex` so the stacked frame has no duplicated labels.

### 3.3 The Bracket Is Not Decorative
`pd.concat` takes a LIST of frames. `pd.concat(df1, df2)` (loose arguments) still works positionally for two frames, but the list form `pd.concat([df1, df2], axis=...)` is the safe habit — required the moment three or more frames are combined.

## 4. Motor-Recall Code Templates

```python
import pandas as pd
merged = pd.merge(patients, labs, on="PatientID", how="left")     # keep all patients
all_rows = pd.concat([df1, df2], axis=0, ignore_index=True)       # vertical
wide = pd.concat([df1, df2], axis=1)                               # horizontal
```

## 5. Exam Question Archetypes

**Archetype — demographics + labs:** "Combine patient demographic tables with diagnostic lab results using a left join on PatientID."
```python
combined = pd.merge(demographics, labs, on="PatientID", how="left")
```

**Archetype — retention pop-quiz:** "Which `how` keeps every row from both tables, NaN-padding the gaps?" — `outer`.

## 6. Self-Audit Checklist

- [ ] Every `pd.merge` states `on=` and `how=`.
- [ ] Mismatched key names use the `left_on`/`right_on` pair.
- [ ] Every `pd.concat` input is a bracketed list with an explicit `axis`.
- [ ] No `df1.concat(df2)` — concat has no instance method form.
- [ ] `ignore_index=True` on row-stacking (unless the labels are data).
