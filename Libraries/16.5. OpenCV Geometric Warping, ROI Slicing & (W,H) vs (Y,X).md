# 16.5. OpenCV Geometric Warping, ROI Slicing & (W,H) vs (Y,X)

> Exam-defense companion to [[16. Image Spatial Transformations - Interpolation, Scaling, Cropping, and Affine Warping]]. This sheet is the Coordinate Inversion Rule armed for battle: dsize order, the `img.resize` trap, ROI slicing, annotation coordinates, and the rotation matrix. Verified on OpenCV 4.13.0.

## 1. Syntax Matrix - What Breaks vs. What Runs

| You are writing... | Correct form | Fatal handwritten form | Failure mode |
| :--- | :--- | :--- | :--- |
| Resize | `cv2.resize(img, (w, h))` | `cv2.resize(img, (h, w))` | No exception — the image comes back **transposed** (aspect inverted). Verified: `resize((200,100)-shaped, (50,25))` -> shape (25, 50). |
| Resize by factor | `cv2.resize(img, (0, 0), fx=0.5, fy=0.5)` | — | dsize=(0,0) signals "use fx/fy". |
| The native-array trap | `cv2.resize(img, ...)` | `img.resize(...)` | `ndarray.resize` is a **raw buffer resize** — it reallocates the flat memory and zero-fills; it does NOT interpolate pixels. Never as image scaling. |
| Crop (ROI) | `img[y1:y2, x1:x2].copy()` | `cv2.crop(...)` | There is no crop function in OpenCV — cropping IS NumPy slicing, Y first. |
| Scale factors | `fx` horizontal, `fy` vertical | swapping them | Swapped factors = distorted aspect. |
| Rectangle | `cv2.rectangle(img, (x1, y1), (x2, y2), (B, G, R), thickness)` | `(y1, x1), (y2, x2)` | Box drawn mirrored on non-square images — silently wrong. |
| Text | `cv2.putText(img, "s", (x, y), cv2.FONT_HERSHEY_SIMPLEX, scale, color, thickness)` | — | `org` is the **bottom-left** corner of the text, in (x, y). |
| Rotation matrix | `M = cv2.getRotationMatrix2D((cx, cy), angle, scale)` | — | 2x3 affine matrix; center in (x, y). |
| Warp | `cv2.warpAffine(img, M, (w, h))` | `warpAffine(img, M, (h, w))` | Same dsize=(w, h) rule as resize. |
| Orthogonal rotation | `cv2.rotate(img, cv2.ROTATE_90_CLOCKWISE)` | `np.rot90` mixing semantics | `np.rot90` also transposes semantics — pick one family per answer. |

## 2. Exact Signatures and Positional Defaults

```python
h, w = img.shape[:2]                                    # H rows, W cols (grayscale-safe)
half = cv2.resize(img, (w // 2, h // 2), interpolation=cv2.INTER_LINEAR)
roi  = img[y1:y2, x1:x2].copy()                         # Y span first, X span second
cv2.rectangle(img, (x1, y1), (x2, y2), (255, 0, 0), 2)  # blue box, thickness px (-1 fills)
cv2.putText(img, "Label", (x, y - 10), cv2.FONT_HERSHEY_SIMPLEX, 0.6, (0, 255, 0), 2)
M    = cv2.getRotationMatrix2D((w / 2, h / 2), 45, 1.0)  # center (x, y), degrees CCW
rot  = cv2.warpAffine(img, M, (w, h))
```

Interpolation flags: `INTER_NEAREST` (fast, jagged), `INTER_LINEAR` (default), `INTER_CUBIC` (sharper up), `INTER_AREA` (anti-alias down).

## 3. Trap Deep-Dives

### 3.1 The Coordinate Inversion Rule (the #1 invariant)
NumPy indexes matrices `[row, col] = [y, x]`. OpenCV geometry speaks Cartesian `(x, y) = (width, height)`. Every geometric parameter — dsize, rectangle points, putText org, rotation center — is (x, y). Every memory access — slicing, pixel read, scanline write — is [y, x]. Write the one-line mantra at the top of your answer sheet: "NumPy [y, x]; OpenCV (x, y)."

### 3.2 Why dsize Is (w, h) — the Layout Reason
`cv2.resize` allocates the OUTPUT buffer from your tuple; output buffers are declared (rows, cols)... no — the C++ signature `cv::Size(width, height)` declares width first. So the tuple you pass IS the buffer declaration in OpenCV's native order: width first. The returned array then reports `(h, w)` in `.shape` because NumPy always reports rows first. The two libraries answer the same question in opposite dialects — this is exactly why the rule must be memorized, not reasoned out under stress.

### 3.3 ROI Cropping Is Pure NumPy
`roi = img[y_start:y_end, x_start:x_end]` — vertical span first. A "crop a 100x200 region starting at x=50, y=30" (100 rows tall, 200 cols wide) is:
```python
crop = img[30:130, 50:250].copy()     # y: 30..130 (100 rows), x: 50..250 (200 cols)
```
`.copy()` detaches the slice view (see [[02.5. NumPy Slicing, Views vs. Copies & Masking Discipline]]).

### 3.4 Annotation Coordinates Are Also Cartesian
Rectangle corners, circle centers, putText origins — all (x, y). The classic exam full-play: draw the bounding box of the ROI you just cropped AROUND that region on the original, with a label above it:
```python
cv2.rectangle(canvas, (50, 30), (250, 130), (255, 0, 0), 2)
cv2.putText(canvas, "ROI", (50, 20), cv2.FONT_HERSHEY_SIMPLEX, 0.6, (0, 255, 0), 2)
```
Note how the SAME four numbers (30, 130, 50, 250) swap places between slicing (y first) and drawing (x first).

## 4. Motor-Recall Code Templates

```python
import cv2
h, w = img.shape[:2]                                 # defensive: works gray AND color
small = cv2.resize(img, (w // 2, h // 2))             # (w, h) - W FIRST
crop  = img[y1:y2, x1:x2].copy()                     # [y, x] - Y FIRST
M = cv2.getRotationMatrix2D((w / 2, h / 2), 45, 1.0)
rot = cv2.warpAffine(img, M, (w, h))                 # (w, h) again
cv2.rectangle(img, (x1, y1), (x2, y2), (255, 0, 0), 2)   # (x, y) points
```

## 5. Exam Question Archetypes

**Archetype — the geometry full-play:** "Crop a 100 x 200 region starting at x=50, y=30, draw a bounding box around it on the original image, and downscale by half."
```python
h, w = img.shape[:2]
roi = img[30:130, 50:250].copy()                     # 100 rows, 200 cols
canvas = img.copy()
cv2.rectangle(canvas, (50, 30), (250, 130), (255, 0, 0), 2)
small = cv2.resize(img, (w // 2, h // 2), interpolation=cv2.INTER_LINEAR)
```

## 6. Self-Audit Checklist

- [ ] Every `resize`/`warpAffine` dsize written (w, h) — width first.
- [ ] Zero `img.resize(...)` calls (buffer op, not scaling).
- [ ] Every ROI slice ordered [y1:y2, x1:x2], with `.copy()` if modified.
- [ ] Every rectangle/putText point ordered (x, y); putText org = bottom-left.
- [ ] `h, w = img.shape[:2]` (not `h, w, c = img.shape` — crashes on grayscale).
