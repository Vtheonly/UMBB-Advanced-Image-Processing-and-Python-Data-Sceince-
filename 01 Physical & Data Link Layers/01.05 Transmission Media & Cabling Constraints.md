### 1.5 Transmission Media & Cabling Constraints (Straight-Through vs. Crossover)

Choosing the correct cable between two Ethernet devices is a recurring short-answer question
(Retake Examination, May 2025). The rule depends on **which device class sits at each end**,
because of how the 8-pin RJ-45 twisted-pair connector wires its transmit (TX) and receive (RX)
pairs.

#### Device Classes by RJ-45 Pinout

| Device Class | Pinout Type | Examples |
| :--- | :--- | :--- |
| **MDI (Medium Dependent Interface)** | Transmits on pins 1–2, receives on pins 3–6 | PCs, servers, printers, routers (router Ethernet interfaces) |
| **MDI-X (Medium Dependent Interface Crossover)** | Transmits on pins 3–6, receives on pins 1–2 (internal crossover) | Switches, hubs |

* **Routers behave like end hosts (MDI):** a router's Ethernet interface transmits on the same
  pins a PC's network card does. This is why router cabling questions follow the *host* rules,
  not the switch rules.
* **Switches and hubs (MDI-X)** already swap the pairs internally.

#### Cable Selection Rule

$$\text{Same device class at both ends} \implies \textbf{Crossover cable}$$
$$\text{Different device classes at each end} \implies \textbf{Straight-through cable}$$

| Connection | Cable | Why |
| :--- | :---: | :--- |
| PC $\to$ Switch | **Straight-through** | MDI $\to$ MDI-X (different classes) |
| Router $\to$ Switch | **Straight-through** | MDI $\to$ MDI-X (different classes) |
| Router $\to$ Router (Ethernet) | **Crossover** | MDI $\to$ MDI (same class) |
| Router $\to$ PC | **Crossover** | MDI $\to$ MDI (same class) |
| Switch $\to$ Switch | **Crossover** | MDI-X $\to$ MDI-X (same class) |
| PC $\to$ PC | **Crossover** | MDI $\to$ MDI (same class) |

> **Exam answers (Retake 31.05.2025):**
> * *"Which cable connects a router directly to another router over Ethernet interfaces?"*
>   $\to$ **Crossover cable.**
> * *"Which cable connects a router directly to a PC?"* $\to$ **Crossover cable.**

#### The Auto-MDIX Caveat

Modern switch interfaces implement **Auto-MDIX**, which automatically detects the required
pinout and swaps TX/RX pairs as needed. When Auto-MDIX is enabled on both ends, either a
straight-through or a crossover cable works — the exam still expects the classical answer
(**crossover for same-class links**) unless the question explicitly mentions Auto-MDIX.

#### Physical Media Recap (Layer 1)

| Medium | Encoding | Reach / Notes |
| :--- | :--- | :--- |
| **Copper twisted pair** (100BASE-TX, 1000BASE-T) | Electrical voltage differentials | 100 m max segment; cheap, dominant in LANs |
| **Optical fiber** | Infrared / laser light pulses | Long distance, immune to electromagnetic interference |
| **Wireless radio (IEEE 802.11)** | Modulated high-frequency electromagnetic waves | No cabling; shared medium requiring CSMA/CA (see [[06.06 IEEE 802.11 Wireless Architecture (CSMA-CA, IFS, DSSS)]]) |

* **Serial WAN links (Router $\to$ Router over Serial):** these do not use RJ-45 Ethernet
  pinouts at all; they use serial cables (V.35 / smart serial) and are cabled DCE$\leftrightarrow$DTE.
  The DCE side must supply the clock: `clock rate 56000` (see [[04.02 Essential Configuration Commands]]).
