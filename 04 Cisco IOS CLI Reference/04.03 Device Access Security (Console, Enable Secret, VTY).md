### 4.3 Device Access Security (Console, Enable Secret, VTY Passwords)

Securing administrative access to a Cisco router or switch is a graded exercise on its own
(CA1, 13.12.2023). The exam expects the exact command sequence, the correct mode for each
command, and the save command at the end.

#### The Three Access Planes to Secure

| Access Path | What It Protects | Configuration Location |
| :--- | :--- | :--- |
| **Console port** (physical) | Anyone with a serial cable plugged into the device | `line console 0` |
| **Privileged EXEC mode** | The `enable` gate to all configuration and destructive commands | `enable secret` |
| **VTY lines** (Telnet/SSH) | Remote administrative sessions over the network | `line vty 0 4` |

#### Graded Configuration (CA1 13.12.2023 — Router 0)

```cisco
Router0> enable
Router0# configure terminal

!-- (1) Secure the console line: password + login enforcement
Router0(config)# line console 0
Router0(config-line)# password passConsole
Router0(config-line)# login
Router0(config-line)# exit

!-- (2) Secure privileged EXEC mode with an ENCRYPTED password
Router0(config)# enable secret passPrivilege
Router0(config)# exit

!-- (3) Persist the configuration to NVRAM
Router0# copy running-config startup-config
```

**Answer pattern (memorize the triple):**
* Console: `line console 0` $\to$ `password <pw>` $\to$ `login`
* Privileged: `enable secret <pw>`
* Save: `copy running-config startup-config` (alias: `write` / `wr`)

#### `enable password` vs. `enable secret` — The Exam Distinction

| Command | Storage | Security |
| :--- | :--- | :--- |
| `enable password <pw>` | Cleartext in the configuration file | Weak — readable in `show running-config` |
| `enable secret <pw>` | MD5-hashed in the configuration file | **Preferred and expected in exams** |

* When both are configured, the **`enable secret` always wins** (IOS ignores the cleartext
  `enable password`).
* Exam answers should use `enable secret` for privileged mode; `enable password` appears mostly
  as a distractor or for pre-12.2 compatibility questions.

#### Securing Remote Access (VTY)

The same line-submode pattern protects Telnet/SSH sessions (lines 0 through 4 = 5 concurrent
remote sessions):

```cisco
R1(config)# line vty 0 4
R1(config-line)# password RemoteAccessPassword
R1(config-line)# login
R1(config-line)# exit
```

* Without `password` + `login` on the VTY lines, Telnet sessions are **refused** by default
  ("password required, but none set").
* `login` enforces password checking; `login local` switches to per-user authentication
  against the local username database (`username X privilege 15 secret Y`).

#### Why `copy running-config startup-config` Matters

| Memory | Contents | Volatility |
| :--- | :--- | :--- |
| **RAM** — running-config | The active configuration currently executing | Lost on reboot/power cut |
| **NVRAM** — startup-config | The saved configuration loaded at boot | Persistent |

Any security configuration that is not saved to NVRAM evaporates at the next reload — the exam
always awards the final mark for the save command.
