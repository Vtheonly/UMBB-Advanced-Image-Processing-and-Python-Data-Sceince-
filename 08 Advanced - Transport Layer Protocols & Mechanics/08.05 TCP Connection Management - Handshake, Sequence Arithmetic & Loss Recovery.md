### 8.5 TCP Connection Management: Handshake, Sequence Arithmetic, and Loss Recovery

### Handshake Sequence
1. **SYN:** Client sends initial connection request:
   $$\text{Control: } \text{SYN}=1, \text{ACK}=0 \quad|\quad \text{Nseq} = \text{ISN}_{\text{client}} \quad|\quad \text{Nack} = 0$$
2. **SYN + ACK:** Server acknowledges client and sends its own initial sequence number:
   $$\text{Control: } \text{SYN}=1, \text{ACK}=1 \quad|\quad \text{Nseq} = \text{ISN}_{\text{server}} \quad|\quad \text{Nack} = \text{ISN}_{\text{client}} + 1$$
3. **ACK:** Client confirms server sequence:
   $$\text{Control: } \text{SYN}=0, \text{ACK}=1 \quad|\quad \text{Nseq} = \text{ISN}_{\text{client}} + 1 \quad|\quad \text{Nack} = \text{ISN}_{\text{server}} + 1$$

### Sequence Arithmetic Rules
* **SYN and FIN flags** each consume **1 sequence number**, even though they carry no payload data.
* **Pure ACKs** (carrying no payload data) consume **0 sequence numbers**.
* **Payload data** advances sequence numbers byte-for-byte:
  $$\text{Next Expected Sequence Number} = \text{Current Sequence Number} + \text{Payload Length (in bytes)}$$

---

#### Rules Observed in Graded Examination Traces

The following behaviors appear consistently in the official solution traces of the TCP flow-diagram exercises ([[09.08 Final January 2024 - Network Design and TCP Flow Control|Final January 2024, Exercise 2]] and [[09.13 Final 2020 - TCP Transport and DMZ Routing|Final 2020, Exercise 1]]):

* **SYN and FIN consume one sequence number each**; pure data-free ACKs consume none.
* Data segments advance the sender's sequence number by their payload length: $\text{Nseq}_{\text{next}} = \text{Nseq} + \text{Len}$.
* ACK numbers are **cumulative**: an ACK of $N$ confirms receipt of every byte up to $N-1$ and requests byte $N$ next.
* When a segment arrives out of order (a gap is detected), the receiver **repeats the ACK of the last in-order byte** (duplicate ACK), implicitly signalling the loss.
* The sender **retransmits only the missing segment** upon receiving duplicate ACKs (fast retransmit behavior in these traces), after which the cumulative ACK jumps forward.
* A FIN may piggyback on the final data segment; the peer's final ACK acknowledges the data and the FIN's consumed sequence number together.
