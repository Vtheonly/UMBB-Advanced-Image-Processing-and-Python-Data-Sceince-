### 6.3 Dynamic Host Configuration Protocol (DHCP) — Full Architecture

DHCP appears on nearly every UMBB paper (CA1 30.11.2023, Finals 14.01.2025, 31.05.2025,
2021–2022, and the 2021–2022 exercise set). It automates the assignment of every parameter a
host needs to communicate.

#### What the Server Assigns (the client parameter list)

* Assigned **IPv4 address** and **subnet mask**
* **Default gateway** IP
* **DNS server** IPs (primary and secondary)
* **Domain name**
* **Directed broadcast** address
* **Lease duration**

#### The DORA Transaction (memorize the order)

| # | Message | Direction | Transport |
| :---: | :--- | :--- | :--- |
| 1 | **DHCPDISCOVER** | Client $\to$ broadcast | UDP 68 $\to$ 67 |
| 2 | **DHCPOFFER** | Server $\to$ client (unicast or broadcast) | UDP 67 $\to$ 68 |
| 3 | **DHCPREQUEST** | Client $\to$ broadcast (accepts one offer) | UDP 68 $\to$ 67 |
| 4 | **DHCPACK** | Server $\to$ client (confirmation) | UDP 67 $\to$ 68 |

> **Sockets:** the server listens on **UDP port 67**; the client listens on **UDP port 68**.
> Both directions ride on UDP — DHCP must work before IP configuration is complete, so no
> connection-oriented transport is possible.

#### Conflict Detection — Who Pings Whom

| Actor | Check | Mechanism | Timing |
| :--- | :--- | :--- | :--- |
| **Server** | Is the candidate IP really free before offering it? | Sends an **ICMP Echo Request (ping)** to the candidate address | Before `DHCPOFFER` |
| **Client** | Is someone else already using the offered IP? | Sends a **Gratuitous ARP** for the offered address | After `DHCPACK` receipt |

If the gratuitous ARP is answered, the client declines the address (`DHCPDECLINE`) and restarts
discovery.

#### The Flags Field — Broadcast Bit

When the **Flags field = 1** in a `DHCPDISCOVER`, the client announces that it **cannot receive
unicast IP datagrams yet** (its IP stack is unconfigured; it may not own the offered address
until the lease is acknowledged). The server must therefore return its replies (OFFER/ACK) as
**broadcasts**, which the client can receive at Layer 2 without an assigned address.

#### Lease Timers — T1 and T2

$$T_1 = 50\% \text{ of lease} \qquad T_2 = 87.5\% \left(= \tfrac{7}{8}\right) \text{ of lease}$$

| Timer | Fires at | Client action |
| :--- | :---: | :--- |
| **T1 (renewal)** | 50% | Sends a **unicast** `DHCPREQUEST` to the **original issuing server** asking to renew |
| **T2 (rebinding)** | 87.5% | If renewal went unanswered, **broadcasts** `DHCPREQUEST` to **any** DHCP server on the network |
| **Lease expiry** | 100% | Address released; client must restart DORA from scratch |

#### Client Reboot Behavior

On reboot the client broadcasts a `DHCPREQUEST` asking for its **previous IP**:
* Lease still valid and free $\implies$ server confirms with `DHCPACK` (fast re-acquisition).
* Address reassigned or invalid for the attached subnet $\implies$ server answers `DHCPNAK`
  $\implies$ client falls back to the full four-packet DORA.

#### Multiple Servers on One LAN

The client's `DHCPREQUEST` is **broadcast** and carries the **server identifier** (the IP of the
chosen server). Every other DHCP server on the segment reads that identifier, understands its
offer was declined, and **returns its tentatively reserved address to the pool**.

#### Serving Several Subnets with One Server — DHCP Relay

A broadcast `DHCPDISCOVER` does not cross routers. To let one central server serve multiple
subnets, configure the **relay agent** on the router interface of each remote subnet:

```cisco
Router(config)# interface FastEthernet 0/1
Router(config-if)# ip helper-address <DHCP_Server_IP>
```

The router converts local broadcast requests into **unicast** packets routed to the central
server (and relays the replies back onto the client segment).

#### Server State Persisted to Disk (power-failure recovery)

A DHCP server must survive abrupt power loss without re-issuing live addresses. It writes to
non-volatile storage:
* **Active IP-to-MAC lease bindings**
* **Lease start and expiration timestamps**
* **Available / unallocated pool ranges**
* **Manual static reservations**

#### DHCP on Linux

* Server configuration file: **`/etc/dhcp/dhcp.conf`** (multiple-choice answer expected
  verbatim — Final 02.02.2023).
* **Can a DHCP server itself obtain its IP from another DHCP server?** Technically **yes**, but
  it is **strongly discouraged**: a server must keep a **static IP** so the service stays
  reachable even if leases expire or the parent server goes down.

#### When DHCP Fails — APIPA / IPv4LL

If no server answers, the host self-assigns a link-local address from **`169.254.0.0/16`**
(Automatic Private IP Addressing / IPv4 Link-Local). Seeing a `169.254.x.x` address on a host
is the classic diagnostic signature of a broken DHCP path.
