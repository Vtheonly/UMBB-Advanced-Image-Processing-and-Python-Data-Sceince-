### 6.4 Network Address Translation (NAT) and Port Address Translation (PAT)

#### 1. The Core Architecture of Address Translation
The rapid growth of the Internet highlighted a major limitation in IPv4: the finite pool of 32-bit address spaces. To address this shortage, RFC 1918 defined three blocks of private IP address spaces that cannot be routed across the public Internet:
* **Class A:** `10.0.0.0/8`
* **Class B:** `172.16.0.0/12`
* **Class C:** `192.168.0.0/16`

Network Address Translation (NAT) was developed to translate private, non-routable IP addresses within an internal network into public, globally routable IP addresses. This translation occurs on a perimeter boundary device, such as a firewall or gateway router, allowing internal hosts to access public Internet resources.

#### 2. Detailed Translation Methodologies: Static, Dynamic, and Overload

##### Static NAT (1:1 Mapping)
Static NAT establishes a permanent, one-to-one mapping between an internal private IP address and an external public IP address.
* **Mechanism:** The translation table remains static. Every packet originating from a specific internal IP is translated to the same public IP.
* **Primary Use Case:** External-facing servers (such as Web, Mail, or VPN gateways) located within an internal private subnet or DMZ that must be accessible from the public Internet.

##### Dynamic NAT (Many-to-Many Mapping)
Dynamic NAT maps an private IP address to a public IP address from a pool of registered public addresses.
* **Mechanism:** When an internal host requests Internet access, the router dynamically assigns an unused public IP address from its pool. This binding remains active for the duration of the communication session.
* **Limitation:** If the public IP pool contains $N$ addresses, only $N$ internal hosts can communicate concurrently. Any additional hosts must wait until an active translation session expires.

##### Port Address Translation / PAT (Many-to-One / Overload)
PAT (also known as NAT Overload) maps multiple private IP addresses to a single public IP address by tracking unique port numbers.
* **Mechanism:** The gateway router tracks connections by using unique source port numbers. If multiple internal hosts initiate outbound connections using the same source port (e.g., source port `49152`), the PAT gateway modifies the source port of subsequent connections to ensure uniqueness (e.g., translating host B's connection to port `49153` on the public IP).

#### 4. Exhaustive Technical Evaluation Matrix

| Evaluation Criteria | Static NAT (1:1) | Dynamic NAT (m:n) | Port Address Translation (PAT) |
| :--- | :--- | :--- | :--- |
| **Definition** | Static 1-to-1 IP address translation. | Dynamic assignment from a pool of public IPs. | Translates multiple private IPs to one public IP using source ports. |
| **Translation Mapping** | Private IP $\leftrightarrow$ Public IP (Permanent) | Private IP $\leftrightarrow$ Public IP (Session-based) | Private IP:Port $\leftrightarrow$ Public IP:Unique Port |
| **IP Pool Demand** | High (one public IP required for each translated server). | Medium (requires a pool proportional to peak concurrent sessions). | Low (allows thousands of hosts to share a single public IP). |
| **Primary Use Cases** | Web servers, Mail servers, secure static tunnels. | Temporary outbound access for small workgroups. | General user Internet access in homes and enterprise networks. |
| **Advantages** | * Supports bidirectional connection establishment (inbound and outbound).<br/>* Reliable and predictable translation. | * Secures internal hosts by keeping them invisible from the outside network when idle. | * Maximizes public IP space efficiency.<br/>* Highly cost-effective.<br/>* Simplifies address planning. |
| **Disadvantages** | * Inefficient use of public IP addresses.<br/>* Expensive to implement at scale. | * Unidirectional initiation only (inbound connections are blocked).<br/>* Sessions fail if the public IP pool is exhausted. | * High router resource overhead (requires maintaining state for thousands of port mappings).<br/>* Complex troubleshooting. |
| **Security Profile** | Moderate (hides private IP, but the host remains exposed via the public IP translation). | High (internal addresses are invisible from outside networks when idle). | Highest (completely conceals internal network topology; blocks unsolicited inbound traffic). |
| **Relative Cost** | High (recurring charges for public IP allocation from the ISP). | Medium to High. | Low (only requires a single public IP address). |

#### 5. The Four Cisco NAT Address Definitions (Final 14.01.2025, Q8)

Cisco formalizes every address in a translation with four terms. Exams ask for them
verbatim:

| Term | Definition | Example (inside net `192.168.1.0/24`, public `203.0.113.5`) |
| :--- | :--- | :--- |
| **Inside Local** | The **private IPv4 address** assigned to a host on the **internal** network | `192.168.1.50` |
| **Inside Global** | The **registered public IPv4 address** that represents an inside host to the **outside** world | `203.0.113.5` |
| **Outside Local** | The IP address of an **external host as it appears to the inside** network (usually identical to its real address) | `93.184.216.34` as seen internally |
| **Outside Global** | The **public IPv4 address** assigned to a host on the **outside** network by its owner | `93.184.216.34` |

> **Memory hook:** *Local = as seen from inside; Global = as seen from the public Internet.*
> Inside/Outside says **which side the host physically sits on**; Local/Global says **which
> side's viewpoint the address is expressed from*.

**Exam answer (14.01.2025):** *Inside Global* = "the public IP address representing an internal
private network to the outside world."

#### 6. Cisco CLI Configuration — Dynamic NAT with Overload (PAT)

```cisco
! 1. Mark the inside and outside perimeter interfaces
Router(config)# interface FastEthernet 0/0
Router(config-if)# ip nat inside
Router(config)# interface Serial 0/1/0
Router(config-if)# ip nat outside

! 2. Define which internal traffic is eligible (standard ACL, wildcard mask)
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255

! 3. Name the public address pool
Router(config)# ip nat pool PUBLIC_POOL 203.0.113.10 203.0.113.20 netmask 255.255.255.0

! 4. Bind ACL + pool, with overload = PAT
Router(config)# ip nat inside source list 1 pool PUBLIC_POOL overload
```

* The keyword **`overload`** is what turns dynamic NAT into PAT (many-to-one): when the pool is
  exhausted, additional flows reuse pool addresses with distinct source ports.
* Single public IP available? Skip the pool and overload the outside interface itself:
  `ip nat inside source list 1 interface Serial 0/1/0 overload`.
* **Static NAT for a DMZ server (1:1):** `ip nat inside source static 172.16.0.129 203.0.113.5`.
* Verification: `show ip nat translations`, `show ip nat statistics`.

#### 7. Port Forwarding vs. Port Triggering

Both make internal servers reachable through a single public address — they differ in who
initiates and how long the hole stays open:

| | **Port Forwarding (Static DNAT)** | **Port Triggering** |
| :--- | :--- | :--- |
| Mapping | **Permanent, static**: public port $P$ $\to$ internal `IP:port` at all times | **Dynamic**: inbound port opens only **after** an internal host sends outbound traffic on a designated **trigger port** |
| Direction | Outside can initiate anytime | Outside can reach in **only during the triggered session** |
| Use case | Public web/mail servers in a DMZ (the `DNAT --to-destination` rule of [[06.05 Linux Routing, Tools & iptables DMZ Forwarding]]) | Gaming / P2P apps whose servers call back on a different port |
| Security | Exposed surface 24/7 | Hole closes automatically when idle |

**Exam answer (14.01.2025, Q5):** *Port Triggering* = "dynamically opens an inbound port in
response to designated outbound traffic."

#### 8. Where NAT Fits in the Exams

* CA1 30.11.2023: which NAT type connects a subnet to the Internet $\implies$ **Dynamic NAT or
  PAT (overload)**.
* Final 2021–2022: ISP-hosted web servers need NAT only if they sit on **private** addresses;
  with public IPs they route natively.
* Final 2020: implement outbound PAT with `iptables -j MASQUERADE` and inbound publishing with
  `-j DNAT` (Linux counterpart of the commands above).
