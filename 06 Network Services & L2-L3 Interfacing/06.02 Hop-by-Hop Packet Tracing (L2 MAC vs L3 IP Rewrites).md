### 6.2 Hop-by-Hop Packet Tracing (L2 MAC vs. L3 IP Rewrites)

Tracing a packet across a multi-router topology and writing the state of its addresses at every
observation point is a guaranteed exam table (CA1, 13.12.2023). The entire exercise rests on
one asymmetry:

> **IP source and destination addresses NEVER change across a routed path (without NAT).
> MAC source and destination addresses are REWRITTEN at every single router hop.**

#### Why the Rewrites Happen

1. **L3 endpoints are global:** the IP addresses identify the true sender and the true final
   receiver. Every router keeps them intact so the packet can be delivered end-to-end and so
   transport-layer replies know where to go.
2. **L2 links are local:** an Ethernet frame only means something on one physical segment. Each
   router:
   * receives a frame addressed to **its own** interface MAC (destination MAC = router ingress),
   * strips the old L2 header and FCS,
   * re-encapsulates the packet with **its own egress interface MAC as source** and the
     **next hop's MAC as destination** (resolved via ARP — [[06.01 Address Resolution Protocol (ARP) Deep Dive]]),
   * computes a fresh FCS.
3. Hosts behave the same way: a sending host addresses the frame to its **default gateway's
   MAC**, never to the remote host's MAC (see [[01.06 Wireshark Hexadecimal Frame Parsing Walkthrough]], Walkthrough 2).

#### The Method (build the exam table)

1. Draw the topology; label every interface with its **IP and MAC**.
2. Identify the router path from source to destination (using routing tables if given).
3. For each hop boundary, fill one row: **IP src / IP dst stay constant; MAC src = the
   transmitting interface of the current device; MAC dst = the receiving interface of the next
   device.**

#### Worked Exam Trace (CA1 13.12.2023)

*Topology:* PC0 (`172.20.20.1`, MAC `AA:AA:AA`, GW `172.20.20.254`) — Subnet 1
`172.20.20.0/24` — R0 `Fa0/0` (MAC `EE:EE:EE`) | R0 `Fa0/1` (MAC `DD:DD:DD`, `10.1.1.1/30`)
— R1 `Fa0/1` (MAC `CC:CC:CC`, `10.1.1.2/30`) | R1 `Fa0/0` (MAC `A1:A1:A1`,
`193.64.68.254`) — Subnet 2 `193.64.68.0/24` — PC1 (`193.64.68.1`, MAC `B1:B1:B1`).

**PC0 pings PC1 — packet state at each observation point:**

| Observation Point | Source IP | Destination IP | Source MAC | Destination MAC |
| :--- | :---: | :---: | :---: | :---: |
| **Exit PC0** (onto Subnet 1) | `172.20.20.1` | `193.64.68.1` | `AA:AA:AA` | `EE:EE:EE` (gateway R0 Fa0/0) |
| **Exit Router 0** (onto WAN link) | `172.20.20.1` | `193.64.68.1` | `DD:DD:DD` (R0 Fa0/1) | `CC:CC:CC` (R1 Fa0/1) |
| **Exit Router 1** (onto Subnet 2) | `172.20.20.1` | `193.64.68.1` | `A1:A1:A1` (R1 Fa0/0) | `B1:B1:B1` (PC1) |
| **Arrival at PC1** | `172.20.20.1` | `193.64.68.1` | `A1:A1:A1` | `B1:B1:B1` |

**Reading the table:**
* The two IP columns are **identical in every row** — end-to-end addresses.
* The MAC pair changes **exactly once per router crossed**: PC0's frame dies at R0; R0's frame
  dies at R1; R1's frame dies at PC1.
* The first row already shows the trick most students miss: PC0 does **not** put PC1's MAC in
  the frame — it puts the **gateway's** MAC, because `193.64.68.1` is off-subnet.

#### Companion Facts Tested in the Same Exam

* **Display the MAC address table on a switch:** `show mac address-table` (or
  `show mac-address-table` depending on IOS version) — run on the **switch**.
* **Display the ARP cache on a PC:** `arp -a` — run on the **host**.
* **True/False trio (answers):**
  * *Same subnet mask $\implies$ same network?* **False** — `10.0.0.1/24` and
    `192.168.1.1/24` share the mask but live in different networks.
  * *Same network $\implies$ same mask?* **True** — hosts on one IP network must agree on the
    mask to agree on the local/remote boundary.
  * *Same network $\implies$ same default gateway?* **False** — a subnet can contain several
    routers; different hosts may point at different gateways (redundancy, load balancing).
