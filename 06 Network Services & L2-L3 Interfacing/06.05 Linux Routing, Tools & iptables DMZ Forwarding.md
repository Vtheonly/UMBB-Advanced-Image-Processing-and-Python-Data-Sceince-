### 6.5 Linux Routing, Diagnostic Tools & iptables DMZ Forwarding

Several exams (Final 2020, and the retake/MCQ banks) test Linux-side networking alongside
Cisco IOS: reading the kernel routing table, tracing Layer 3 paths, and programming the
netfilter firewall with `iptables` to implement NAT and DMZ port forwarding.

#### Diagnostic Command Reference

| Task | Command | Notes |
| :--- | :--- | :--- |
| Display the kernel routing table | `route -n` or `netstat -rn` | `-n` prints numeric addresses (no DNS lookups); equivalent modern tool: `ip route` |
| Trace intermediate Layer 3 hops | `traceroute <ip>` | Exploits the TTL mechanism: each router that decrements TTL to 0 returns ICMP Time Exceeded, revealing itself |
| Display the ARP cache (hosts) | `arp -a` | Same answer as on Windows exams — host-side, not router-side |
| List firewall/NAT rules | `iptables -t nat -L -n` / `iptables -L -n` | Filter table is default; NAT rules live in the `nat` table |

> A Linux box acting as a router must have forwarding enabled:
> `echo 1 > /proc/sys/net/ipv4/ip_forward` (or `sysctl net.ipv4.ip_forward=1`).

#### Reading a Linux Routing Table

```text
Destination     Gateway         Genmask         Flags  Iface
172.16.0.0      0.0.0.0         255.255.255.128 U      eth0
0.0.0.0         174.199.25.254  0.0.0.0         UG     eth_wan
```

* `Gateway 0.0.0.0` + `Iface` $\implies$ **directly connected** network (no next hop needed).
* `0.0.0.0/0` via a gateway $\implies$ the **default route** — identical semantics to Cisco's
  `ip route 0.0.0.0 0.0.0.0 <next-hop>`.

#### iptables — Packet Filtering and NAT Framework

`iptables` processes packets through ordered rule chains inside **tables**:

| Table | Chains | Purpose |
| :--- | :--- | :--- |
| `filter` (default) | INPUT / FORWARD / OUTPUT | Accept, drop, or reject packets |
| `nat` | PREROUTING / POSTROUTING / OUTPUT | Rewrite source or destination addresses (DNAT/SNAT) |

* `-A <chain>` appends a rule; `-t <table>` selects the table; `-j <TARGET>` jumps to an action
  (`MASQUERADE`, `DNAT`, `ACCEPT`, `DROP`...).

#### Outbound Internet Access — SNAT / Masquerading (PAT)

All internal private hosts share the single public IP of the gateway. Source addresses are
rewritten on the way out (POSTROUTING), with unique source ports tracking each flow — exactly
the **PAT / NAT Overload** of [[06.04 Network Address Translation (NAT) & Port Address Translation (PAT)]]:

```bash
# Masquerade: rewrite every outbound packet's source to the exit interface's public IP
iptables -t nat -A POSTROUTING -o eth_wan -j MASQUERADE
```

On a Cisco perimeter router the same function is `ip nat inside source list 1 pool PUBLIC overload`.

#### Inbound DMZ Publishing — DNAT / Port Forwarding

To expose an internal web server (DMZ at `172.16.0.129`) through the public IP
`174.199.25.77`, rewrite the **destination** before routing (PREROUTING):

```bash
# Incoming TCP :80 to the public IP is redirected to the DMZ web server
iptables -t nat -A PREROUTING -p tcp -d 174.199.25.77 --dport 80 \
         -j DNAT --to-destination 172.16.0.129:80
```

External users browse to `174.199.25.77:80`; the Linux gateway transparently forwards the
connection to `172.16.0.129:80`. This is **static Destination NAT (port forwarding)** — the
iptables counterpart of the Cisco DMZ design graded in [[09.13 Final 2020 - TCP Transport and DMZ Routing]].

#### Cisco Equivalent (for the same exam answers)

```cisco
Router(config)# interface FastEthernet 0/0
Router(config-if)# ip nat inside
Router(config)# interface Serial 0/1/0
Router(config-if)# ip nat outside
Router(config)# access-list 1 permit 172.16.0.0 0.0.0.255
Router(config)# ip nat inside source list 1 interface Serial 0/1/0 overload
```
