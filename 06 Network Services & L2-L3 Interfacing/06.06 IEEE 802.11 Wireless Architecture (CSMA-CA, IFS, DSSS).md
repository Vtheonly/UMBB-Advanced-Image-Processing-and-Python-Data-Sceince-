### 6.6 IEEE 802.11 Wireless Architecture (CSMA/CA, IFS, NAV, DSSS)

Wireless LAN mechanics appear in the Master 1 exams (Final 2020, Dr. Djerbi papers). The radio
medium differs from Ethernet in one decisive way, and every mechanism below exists because of
it.

#### Why Wireless Cannot Use CSMA/CD

| | CSMA/CD (802.3 wired) | CSMA/CA (802.11 wireless) |
| :--- | :--- | :--- |
| Full name | Collision **Detection** | Collision **Avoidance** |
| Strategy | Transmit, listen for collisions, react | Sense channel, wait, then transmit to **avoid** collisions |
| Why | A transceiver can talk and listen on a cable simultaneously | A radio **cannot transmit and receive at the same time** — its own transmission drowns out any incoming signal |
| On collision | Detect voltage spike $\to$ send jam signal $\to$ run backoff algorithm | Cannot detect a collision in progress; must prevent it beforehand |

Because a wireless station can never hear a collision while transmitting, 802.11 abandons
detection entirely and **avoids** collisions using inter-frame waits, virtual carrier sensing,
and explicit handshakes.

#### The Inter-Frame Space (IFS) Hierarchy

Stations must wait a fixed idle period after the channel goes quiet before they may contend.
The waiting class determines priority:

$$\textbf{SIFS} < \textbf{PIFS} < \textbf{DIFS}$$

| IFS | Duration | Priority | Used By |
| :--- | :---: | :--- | :--- |
| **SIFS** (Short IFS) | $10\ \mu s$ | Highest — sent first | Immediate responses: **ACK**, **CTS**, subsequent fragments of a burst |
| **PIFS** (PCF IFS) | $30\ \mu s$ | Medium | Access points operating in **Point Coordination Function** (polling) mode |
| **DIFS** (DCF IFS) | $50\ \mu s$ | Lowest — ordinary data | All ordinary distributed-contention stations: sense idle for the full DIFS, then decrement the backoff counter |

Shorter wait = higher priority: an ACK (SIFS) always beats a new data frame (DIFS) to the
medium, so acknowledgements are never starved.

#### Virtual Carrier Sensing — the NAV

Every 802.11 frame carries a **Duration** field announcing how long the exchange will occupy
the medium. Non-participating stations read it and set their **Network Allocation Vector
(NAV)** — a hardware countdown timer during which they stay silent **without even sensing the
channel**. The NAV plus physical sensing together implement "virtual carrier sense."

#### RTS/CTS and the Hidden Node Problem

Two stations that cannot hear each other (walls, distance) but share an access point can
transmit simultaneously and collide at the AP — the **hidden node problem**. The remedy is a
**Request To Send / Clear To Send** handshake at data-link level:

```text
Sender          Access Point          Receiver (hidden from Sender)
  |--- RTS (Duration set) ------------->|                          |
  |                       |<-- CTS (Duration set) ------------->|  |
  |--- DATA ----------------------------------------------------->  |
  |                       |<----------------------------- ACK -----|  |
```

1. Sender broadcasts **RTS** announcing the intended transmission duration.
2. The AP replies **CTS** (after SIFS), also carrying the duration — now **every** station,
   including hidden ones, updates its NAV.
3. Data flows; the receiver returns an ACK after SIFS.
Because the CTS reaches stations the sender cannot reach, everyone defers — collisions due to
hidden nodes are avoided.

#### DSSS and the Barker Sequence

802.11b's Direct Sequence Spread Spectrum spreads each data bit across a wider band using an
**11-bit Barker chip sequence**:

| Data bit | Chip sequence transmitted |
| :---: | :--- |
| Binary **1** | `11101100011` |
| Binary **0** | `00010011100` (inverted Barker sequence) |

*Example exam question:* given the chip stream, decode bit sequences by matching 11-chip
groups against the two patterns above (e.g. `10101` as data bits maps to the alternating
concatenation of the two chip words).

**Why spread the spectrum?**
* **Interference resistance** — the receiver correlates against the known chip sequence; noise
  averages out.
* **Multi-path tolerance** — correlated echoes reinforce; random reflections do not match the code.
* **Low probability of interception/eavesdropping** — the signal is unintelligible without the
  spreading code and appears as background noise to narrowband receivers.

#### 802.11 Frame and Addressing Snapshot

* 802.11 frames carry up to **four address fields** (receiver, transmitter, BSSID, optional
  destination/source in bridging) versus Ethernet's two — needed because frames cross the AP.
* EtherType-style payload identification continues inside the 802.11 frame exactly as in
  [[01.02 Ethernet Frame Structure & Header Decoding]] (e.g. `0x0800` = IPv4).
* Shared-medium contention is why a Wi-Fi LAN behaves like a **single collision domain** for
  all associated stations — the wireless analog of the hub in
  [[01.03 Layer 2 Network Infrastructure (Hubs vs. Switches)]].
